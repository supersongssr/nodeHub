# 统一「节点被墙」判定口径 — 入向唯一真源方案

> 背景: 2026-09-01 h132 (150.129.10.140) 事件 · 涉及 nodeHub + ServerStatus-Rust-Moniter
> 状态: 方案 (待评审实施)

## 1. 问题: 三套系统、两种方向、「被墙」一词互相打架

| 系统 | 测量方向 | 口径 | h132 实测结果 |
|---|---|---|---|
| ① nodeAgent/proxyDiagnose (节点侧) | **入向** CN→节点:port (tcp.ping.pe) | 三网+云厂全断+海外通=被墙; 交叉验证分端口级/IP级 | v4 三网全断 → IP级被墙 |
| ② 监控层 cn_port_check (中央) | **入向** 同① (每日全量节点) | 分组: ct/cu/cm/vendor, 组内全超时+海外通=该组 blocked | (同①, 入向真源) |
| ③ stat_client 三网丢包 (节点→CN 目标) | **出向** 节点→CN | ping_189/10010/10086 丢包率>99% | 联通100%丢包, 电信7%, 移动0% →"仅联通被墙" |

### 1.1 h132 事件的完整实测 (2026-09-01)

- **入向 v4**: 13 大陆点对 22/80/18153/随机口 + ICMP 全部超时 (12:20/17:xx/18:xx 三时段复现); check-host.net 15 海外节点 18ms-1.4s 全通 → **v4 入向三网全断, 真实 IP 级**
- **入向 v6**: tcp.ping.pe 云厂点通 (1.8s 慢但成功); **本机 8 条 ESTABLISHED 全部为联通 IPv6 用户 (2408::/20)** → v6 活着
- **出向**: ICMP 到三网骨干目标 100% 丢包; TCP 到 baidu 0.49s 通; stat_client 上报 联通断/电信移动正常 (TCP 口径)
- **地面真值**: 节点 v4 用户连接数 = 0, 当日 ~1GB 流量全走 v6

→ ①③ 都"对", 但方向相反; 用户看③ 以为"仅联通被墙、电信移动能用" → **误判** (v4 无人能连)。
→ GFW 跨境封锁的方向性: 丢「CN→境外被标记 IP」的新建连接 (SYN 黑洞), 放行「境外→CN」及其回程 → 出向测试天生不能作为被墙判据。

### 1.2 现存口径混乱 (监控层自查结论 .tmp/findings/04)

③ 的 ping_* 数据在监控层派生了 **A-F 六套**「被墙」口径 (99%/80%、OR/AND/≥2网、峰值/加权), 跨页对比必然打架。根因: 同一动词 "被墙" 挂在出向数据上。

## 2. 方案: 「被墙」全系统只保留一个定义 = 入向

**判定标准 (唯一)**: 大陆探测点 → 节点 `NODE_PORT` 的 TCP 可达性 (用户真实路径), 分 v4/v6 双栈。
stat_client 三网数据**降级为「出向质量参考」**, 只展示、不判定、不告警。

### 2.1 状态机 (最终裁决, 由入向探测 + 出向参考 + 连接真值合成)

| # | 状态 | 条件 | 处置 |
|---|---|---|---|
| S0 | OK | v4 入向通 | — |
| S1 | 端口级被墙 (v4) | 主端口三网断 + 交叉验证新端口通 | **换端口重装由面板远程下发** (nodeAgent 已移除本地自愈, 仅检测/推送/迁移通知 — 2026-09-05 起) |
| S2 | v4 IP级被墙, v6 正常 | v4 三网断 + 新端口亦断 + v6 入向通 | 通知; 面板剔除 A 记录/保 AAAA; 规划换 v4 IP ★h132 现状 |
| S3 | 双栈 IP级被墙 | v4+v6 均三网断 + 海外通 | 真死: CDN/中转/换 IP |
| S4 | 机房侧断连 | 入向断 + 出向三网 TCP 亦全断 + 海外通 | 联系机房 (非 GFW 特征) |
| S5 | 无法判定 | 探测服务异常/样本不足 | 复测 (当日≤3次), 不告警"被墙" |

出向三网 (stat) 只作为 S2/S3/S4 的辅助分型信号 + 页面"出向质量"列。

### 2.3 为什么不改 stat_client

- 出向数据结构上测不了入向, 任何"统一到出向"的方案都会把 h132 判成"仅联通被墙" → 持续误导处置;
- stat_client 的真实价值 (出向路由质量/机房互联健康) 完整保留, 只换标签;
- 零改动第三方二进制, 升级不受影响。
